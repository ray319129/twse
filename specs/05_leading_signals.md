# 領先 / 醞釀型訊號 v1

## 為什麼要有這一類

原本的 12 條策略幾乎都是「**確認型 / 追勢型**」:多頭排列、突破季線、N 日新高、量價齊揚……
它們的設計目的是「等漲勢確立後才告訴你」,所以**結構上一定延遲** —— 訊號到手時股票常常已經漲一段。

這一類「領先訊號」反過來,目標是在**發動之前**就先把候選撈出來,放進 email 的「【四】醞釀區」。

> ⚠️ **天下沒有白吃的午餐:越早 = 假訊號越多。**
> 醞釀區是「觀察名單 / 口袋名單」,不是買進清單。正確用法:先盯著,等它後續真的出現
> 量價發動、或對照前面的追勢訊號同時亮燈,才是較完整的進場依據。

參數都在 `config/screeners.yaml` 的 `leading:` 區塊。

---

## F1. 盤底蓄勢 / 波動壓縮 (Coiling Squeeze)

**條件**(兩者任一,且需通過防護):
- (相對) 布林帶寬度 `bb_width = (上軌-下軌)/中軌` 落在近 `lookback`(120)日最低 `width_pct`(15%)分位,或
- (絕對) `bb_width < abs_width_max`(0.06,即帶寬 ±3% 內)
- 防護:量縮(`vol_ma5 < vol_ma20`)+ 收盤未跌破季線 `near_ma60_tol`(10%)以上

**白話**:大漲之前通常先「安靜地縮」。波動收斂代表多空在狹幅僵持、能量壓縮,一旦帶量突破常有一波。

**為什麼領先**:壓縮發生在發動「之前」,不像突破是發動「當下/之後」。

**會失效**:盤整可能向下假突破;久盤的個股也可能繼續盤。需搭配突破確認。

**適合**:長期橫盤打底、量能萎縮的股票。

---

## F2. 回測支撐 (Pullback to Support)

**條件**:
- 趨勢仍在:季線(60MA)較 20 日前上揚,且收盤站在季線之上
- 自近期高點(近 `lookback_high`=20 日)回檔 ≥ `min_drawdown`(5%)
- 收盤回到 20MA 或 60MA 的 ±`near_pct`(3%)內(或近 3 日最低點曾觸及 20MA)
- `require_turn_up`:今日收紅,或 KD 交叉向上

**白話**:與其追突破(慢一天),不如在「**多頭趨勢中、剛回測均線、開始轉強**」時接回檔。買得更便宜,且在下一段發動之前。

**為什麼領先**:買在拉回的低點,而不是突破的高點。

**會失效**:把「跌破趨勢」誤判成「回測」。所以嚴格要求季線仍上揚 + 收盤在季線之上,避免接刀。

**適合**:已確立多頭、波段操作、想壓低成本的人。

---

## F3. 相對強勢領頭羊 (Relative Strength Leader)

**條件**:
- 近 60 日報酬贏大盤:`rs_ratio = (個股60日報酬)/(大盤60日報酬) ≥ rs_min`(1.0)
- 相對強弱線仍走揚:`rs_line = 個股收盤/大盤收盤`,今日 > `rising_days`(10)日前

**白話**:資金輪動時,下一段主流往往**先在相對強度上露出馬腳** —— 股價創新高之前,相對強弱線常常先創高。大盤回檔時還能維持 `rs_ratio > 1`、`rs_line` 續揚的,就是領頭羊。

**為什麼領先**:相對強度通常領先絕對價格。大盤(`^TWII`)整個 run 只抓一次,`index_below_ma20` 為真時(大盤弱)出現的相對強勢更值得留意,email 會特別標示。

**設計備註**:判斷「仍在轉強」用 `rs_line` 而非 `rs_ratio` 的動能 —— 穩定領漲的股票其 60 日報酬比值會自然鈍化,用 `rs_line` 才不會把「穩定領頭羊」誤殺。

**會失效**:強勢股回檔起來也兇;需配合大盤位階與量能。

## F4. 籌碼吸籌 (Chip Accumulation)

**條件**:
- 近 `lookback`(10)個交易日,三大法人有 ≥ `min_buy_days`(6)天淨買超,且累計淨買為正
- 但近 20 日股價持平:`|20日報酬| ≤ flat_ret20_max`(8%)→ **價格還沒動**

**白話**:主力在「**還沒漲的安靜股票**」裡默默連續買超,是最領先的訊號 —— 籌碼通常領先價格。

**架構修正(重要)**:原本系統只在「價格訊號已觸發、或在自選池」時才抓籌碼,
結構上**根本看不到「法人在偷買、價格還沒動」的股票**。
現在新增前置篩 `_is_quiet_base()`(布林帶寬在低檔 + 股價持平),
為這些安靜股額外抓籌碼,並用 `max_scan`(120)上限控制每日 FinMind API 用量。

**會失效**:法人買超也可能是調節/避險;短期淨買不保證後續發動。

## 同場加映:修正的舊 bug

`eps_positive_high_yield`(EPS+高殖利率)與 `保守存股` combo 原本**永遠不會觸發** ——
因為 `main.py` 把 `per_df=None` 寫死,而殖利率只存在 `per_df`。
現已改為:殖利率優先用 `per_df`,沒有就退而採用每日抓取的全市場估值快照
(TWSE BWIBBU,`valuation_snapshot`)的 `yield_pct`。
