# 當沖策略說明（2026-09-09 現況）

這份文件描述 `scripts/daytrade/` **實際在跑的邏輯**，不是規劃。
參數值直接對應 `config/daytrade.yaml` 與 `config/daytrade_prefs.json`。

> ⚠️ 這一層還在**驗證期**，沒有任何實績證據。專案既有的波段台帳已經驗出
> 「動能是 beta 不是 alpha、線上台帳是負 alpha」，而當沖的成本是波段的 3 倍。
> 請等台帳累積一個月後再判斷這套值不值得用。

---

## 一、核心前提：成本門檻 0.52%

```
手續費（買+賣）  0.1425% × 0.6 × 2 = 0.1710%
當沖證交稅（賣出）              = 0.1500%
進出各跨一檔價差（掃單）        = 2 × tick%
─────────────────────────────────────────
固定部分                        = 0.3210%
```

**tick 是非線性的六級距**，所以同樣的策略在不同價位帶成本差很多：

| 股價 | tick | 1檔% | 來回總成本 | |
|---|---|---|---|---|
| 99 | 0.10 | 0.101% | **0.523%** | ★ 最便宜 |
| **105** | **0.50** | **0.476%** | **1.273%** | ✗ 最貴（2.4 倍） |
| 499 | 0.50 | 0.100% | 0.521% | ★ |
| 1200 | 5.00 | 0.417% | 1.154% | ✗ |

規律：**tick 換檔的正上方最貴、正下方最便宜**。
危險帶 100–130 / 10–16 / 500–560 / 1000–1300，系統預設用 `max_cost_pct: 0.9` 排除。

一天做 3 筆 = 要先賺 **1.56%** 才打平。這是整套設計的出發點：
**價值在「拒絕」，不在「找更多」。**

## 二、盤前：怎麼選出今日推薦

每交易日 08:45（`Premarket Watch` 跑完後由 `workflow_run` 觸發）執行 `--pool`。

### 步驟 1：法規閘門（fail closed）

六個免費 OpenAPI，抓不到一律當「不可做」：

| 閘門 | 來源 | 擋誰 |
|---|---|---|
| 可當沖標的 | TWSE `TWTB4U` / TPEx `tpex_securities` | 不在白名單 → 兩邊都擋 |
| 暫停先賣後買 | 同上的 `Suspension` 欄 | **只擋空方** |
| 處置股 | `announcement/punish` / `tpex_disposal_information` | 兩邊都擋 |
| 注意股 | `announcement/notice` / `tpex_trading_warning_information` | 不擋，只標示 |
| 券差借券費 | `tpex_intraday_fee` | 空方：超過 `max_borrow_fee_pct: 0.5%` 就擋，且**費率加進成本** |

> ⚠️ `Suspension="Y"` 是「暫停先賣後買」不是「不能當沖」——名單裡有台泥、瑞昱
> 這種大型股，原因是除權息停止過戶。當成「不能當沖」會少掉一堆可做標的。

**做空的尾端風險**：先賣後買收盤沒買回 → 券差 → 券商代為借券 →
當日 15:30 前沒補款會**報違約交割**。那不是虧錢，是信用問題。

### 步驟 2：使用者條件（`daytrade_prefs.json`，網頁可調）

| 條件 | 目前值 |
|---|---|
| 價格區間 | 20 – 300 元 |
| 日均成交額 | ≥ 200 百萬 |
| ATR%（日均波動） | 2% – 12%，**硬條件** |
| 來回成本上限 | 0.9% |
| 額度買不起一張 | 直接剔除 |

### 步驟 3：方向判斷（2026-09-09 新增）

五個**互相獨立**的條件投票，每個 ±1，加總歸一化成 −1 ~ +1：

1. 收盤 vs 5 日線
2. 5 日線 vs 月線
3. 收盤 vs 月線
4. 月線 vs 季線
5. RSI（≥55 投多、≤45 投空、中間不投）

`|bias| < min_direction_bias (0.3)` → **方向不明，多空兩邊都不推**。

> 為什麼要有這個：第一版完全沒有方向判斷，同一檔只要通過閘門就同時進多空兩份清單，
> 實測 60 檔裡 **51 檔重複**。那不是推薦，是把最難的部分丟回給使用者。
> 加上這道之後重複降到 **0**，方向不明擋掉 33 檔。

### 步驟 4：排序

**`edge_ratio = ATR% ÷ 來回成本%`**（一天的波動能覆蓋幾次來回成本），必須 ≥ 3.0。

排序分 = `edge × 0.6 + 流動性 × 0.2 + 成本便宜度 × 0.2`

> 第一版用流動性主導，結果前八名是兆豐金、華南金、第一金——成交額大、成本低，
> 但**一天走不到 1%**，對當沖毫無意義。流動性只該是「能不能進出」的及格條件。

## 三、交易計畫怎麼算

停損**先**決定，其他都從它推出來（當沖唯一硬約束是當天必須平掉，風險要先框死）。

```
停損距離 = 日ATR(14) × 0.4        ← 不是 1.0！ATR 是整天區間，當沖只做幾小時
         下限 2 個 tick            ← 否則一跳就出場
目標價   = 進場 ± 停損距離 × 1.5   ← 若超過 20 日高/低，改用那個水位並標記
張數     = min(單筆預算買得起, 風險預算允許)
預計獲利 = (目標−進場) × 張數 × 1000 − 來回成本    ← 一律扣成本才顯示
最大虧損 = (進場−停損) × 張數 × 1000 + 來回成本
```

**所有價格對齊 tick**，進場價保守取整（多方往上、空方往下）——
寧可算出來的預期獲利略低，也不要用搶不到的價位算出漂亮數字。

**算不出來就回 `None`**（ATR 缺 / 價格 0 / 停損小於一個 tick），不給猜的數字。

## 四、額度（當日累計，不是單筆）

> 「我的額度為 25 萬，**一天內買賣超過 25 萬會無法成立**」

所以：
- `used` = 今日**所有**部位（含已平倉）的 `進場價 × 張數 × 1000` 加總
- `remaining` = 額度 − used
- **單筆預算 = remaining × `quota_per_trade_pct`（預設 50%）**

預設 50% 的意思是「留一半給下一個機會」；想單押就設 100。
額度與百分比都可在網頁「⚙ 調整條件」改，寫回 `config/daytrade_prefs.json`。

**單筆風險上限**：`max_risk_pct_of_quota: 2.0`——部位大小取「買得起」與
「風險預算允許」的**小者**。只看買得起的話，停損寬的標的會一次押掉太多風險
（實測台半用滿額度時單筆最大虧損是 25 萬的 4.3%）。

## 五、盤中：訊號怎麼觸發

09:00–13:35 常駐盯盤，無訂閱時每 30 秒一輪（MIS 是非官方端點，打太密會被 ban）。

### 只做「價位穿越」，不做動能追逐

端到端延遲 30 秒–3 分半（輪詢 + Discord 合併視窗 + 人看手機下單）。
這個延遲**追不到動能**，但「價位穿越」不一樣——水位是盤前算好的，
訊號的意思是「它剛穿過 105.2 了」，晚 30 秒通常還在可執行區間。

**水位種類與權重**：

| 水位 | 權重 | 說明 |
|---|---|---|
| 開盤區間上/下緣 | 1.00 | 09:00–09:15 的高低，當沖最主流的參考 |
| 昨日高 / 低 | 0.85 | |
| 均價 VWAP | 0.70 | 無訂閱時是自行輪詢累積的估計值 |
| 整數關卡 | 0.50 | 心理價位，常穿了又回 |

要穿過 **0.2% 緩衝**才算（防貼著水位來回磨）。第一輪不觸發（只建基準）。

### 訊號分級（0–100）

四個因子，全部問「這筆做起來划不划算」而不是「它漲得多兇」：

```
分數 = 水位品質 × 0.30 + 空間(edge) × 0.30 + 量能 × 0.20 + 位階 × 0.10 + 成本便宜度 × 0.10
```

- **位階**會扣分：已漲/跌超過 6% 再追，係數降到 0.25（追高殺低的期望值最差）
- 低於 `min_score: 55` 連網頁都不列
- **多空各自只推前 3 名**（`push_top_n: 3`）到 Discord，其餘只進台帳當**對照組**
- 同一檔冷卻 20 分鐘、同一檔同一水位同方向當日只推一次

## 六、風控與強制回補

| 時間 | 急迫度 | 內容 |
|---|---|---|
| 停損被觸及 | critical | 立即單獨推播（@here） |
| 13:00 | info | 還有 30 分鐘收盤 |
| 13:15 | warn | 剩 15 分鐘，建議開始平倉 |
| 13:25 | **critical** | 剩 5 分鐘——沒平掉就會變成券差/交割 |

有做空部位時，訊息會額外講明券差 → 違約交割的後果。

**風控通知一律單獨發一則**，不進 Discord 的 150 秒合併視窗——
它跟機會提醒的急迫度完全不同。

> 這一層**不需要預測任何東西**，也**不受延遲影響**——13:00 提醒你手上還有 3 筆
> 沒平，晚 30 秒毫無差別。所以它是整個當沖層裡價值最高的部分。
> 但它需要你**做了單就順手在網頁登記**，否則系統不知道你手上有什麼。

## 七、台帳（驗證機制）

每筆推播**與未推播**都記進 `data/daytrade/ledger-YYYY-MM-DD.json`，
追蹤推播後 5 / 15 / 30 / 60 分鐘的價格。

`excess_pct` = 方向調整後的報酬 **− 來回成本**。正值才代表這筆真的有賺頭。

`summarise()` **分開算 pushed 與 not_pushed 兩組**——
兩者的差距就是訊號分級本身的價值。**如果兩組沒差，要調的是分級邏輯，不是推更多。**

---

## 八、目前已知的限制

1. **MIS 盤中真實延遲尚未量到**（排程事故導致盯盤沒跑）。若實測 >60 秒，
   第五節的「價位穿越」層價值有限，應降級成純記錄，重心移到標的池/風控/台帳。
2. **方向判斷只用日線均線**，沒有用到當日盤中結構。盤中反轉時方向會慢半拍。
3. **沒有任何實績證據**。台帳從 2026-09-08 才開始累積。
4. 無訂閱時掃描宇宙限 60 檔（MIS 是逐檔查、50 檔一批），有訂閱可放大到 200。
